# MONTA builds AI-powered video editing automation

MONTA is a **14-layer AI video editing platform** that transforms natural language prompts into fully edited, cinematic videos, and it is approximately **45-50% complete**. The intelligence core (Layers 3-7) — spanning prompt understanding, context composition, director planning, video analysis, and story architecture — is substantially implemented with **199 passing tests** and a functional end-to-end pipeline in the Celery worker. However, the execution layers (8-13) that handle styling, timeline generation, audio, editing, criticism, and rendering remain **stubbed in the master graph**, and the vision, speech, and local-model modules are almost entirely placeholder code. The project is suitable for internal alpha but requires an estimated **33-40 additional engineer-weeks** plus a labeling budget to reach production-grade maturity. The critical path forward runs through real model validation, human judgment data collection, and production hardening before the platform can serve external users.

## MONTA automates the full video editing pipeline

MONTA's core promise is captured in its tagline: "Tell MONTA what you want. It edits for you" ([README.md](file:///Users/karthikeyaunnam/Documents/MONTA/README.md)). The platform accepts natural language descriptions of desired videos and automates the entire editing workflow — understanding footage, composing narratives, grading colors, syncing audio, and rendering final exports — across **14 architectural layers**. These layers span a user-facing Next.js frontend, a FastAPI backend, LangGraph orchestration with Celery async workers, and media processing powered by FFmpeg, OpenCV, and Whisper ([architecture_overview.md](file:///Users/karthikeyaunnam/Documents/MONTA/research_notes/MONTA project status and roadmap/architecture_overview.md)).

The system's architecture separates creative intelligence from technical execution. The intelligence layers (3-7) handle interpretive work: the Prompt Intelligence Engine parses user intent using a lexical ensemble of approximately **400 cues** plus LLM extraction, the Context Composer assembles platform rules and user preferences into immutable context packs, the Director Agent plans and executes a DAG of tasks with bounded concurrency and retry policies, the Video Intelligence Team analyzes clips through FFmpeg-based signal analysis and vision models, and the Story Architect assembles narratives from **10 story patterns** using weighted selection across intent fit, footage fit, and memory priors ([implementation_status.md](file:///Users/karthikeyaunnam/Documents/MONTA/research_notes/MONTA project status and roadmap/implementation_status.md)). The execution layers (8-13) translate creative decisions into rendered output: the Style Engine applies visual presets, the Timeline Generator converts story plans to timeline IR, the Audio Studio handles music and sound, the Edit Executor compiles FFmpeg filtergraphs, the Critic System evaluates output quality, and the Render Farm produces final MP4s ([architecture_overview.md](file:///Users/karthikeyaunnam/Documents/MONTA/research_notes/MONTA project status and roadmap/architecture_overview.md)).

The tech stack is modern and cloud-native: a **Next.js frontend** with a functional core loop (project creation, upload, progress tracking via WebSocket, and results viewing), a **FastAPI backend** with approximately 65% of endpoints implemented, **LangGraph + LangChain** for agent orchestration, **Celery with Redis** for async task processing, **PostgreSQL 16** with SQLAlchemy async and Alembic migrations for persistence, **Qdrant** for vector memory (planned but not yet integrated), and AI models from **Google Gemini, DashScope Qwen, and OpenAI-compatible endpoints** accessed through a unified provider abstraction with circuit breakers and fallback ([architecture_overview.md](file:///Users/karthikeyaunnam/Documents/MONTA/research_notes/MONTA project status and roadmap/architecture_overview.md); [docker-compose.yml](file:///Users/karthikeyaunnam/Documents/MONTA/docker-compose.yml)).

## Intelligence core is functional with 199 passing tests

The bottom-up development approach prioritized infrastructure first: three milestones built the local AI runtime, FFmpeg media engine, and end-to-end pipeline, followed by a large refactor and bug-fix commits across **6 total commits** ([implementation_status.md](file:///Users/karthikeyaunnam/Documents/MONTA/research_notes/MONTA project status and roadmap/implementation_status.md)). The intelligence layers emerged from this process as the mature core of the system. Layers 3-7 are at approximately **70-80% completion** individually, with the Prompt Intelligence Engine handling typos, slang, negation, and conflicting intents through its normalizer (which draws on a **210,000-word English wordlist**) and schema-bound LLM extraction, the Context Composer supporting YouTube, Instagram, TikTok, and YouTube Short platform rules with explicit and inferred preference precedence, and the Director Agent implementing cycle detection, unique ID validation, and partial-failure handling in its DAG executor ([implementation_status.md](file:///Users/karthikeyaunnam/Documents/MONTA/research_notes/MONTA project status and roadmap/implementation_status.md)).

Test coverage reflects this maturity. The suite includes **33 test modules** spanning prompt engine edge cases, API endpoints, director parallelism and timeout handling, intelligence signal analysis and fusion, story pattern validation and repair, timeline IR contracts, FFmpeg compiler output, edit plan validation, provider resilience, calibration fitting, arbitration consensus, observability metrics, local AI runtime preflight, offline mode, and full end-to-end pipeline and golden scenario tests ([implementation_status.md](file:///Users/karthikeyaunnam/Documents/MONTA/research_notes/MONTA project status and roadmap/implementation_status.md)). The golden dataset regression — **14 projects across 7 categories** — achieves a **71% pass rate** (10/14, up from 50% before launch fixes), with story judge scores of 7.68/10 and 93% validity. The Layer 6 synthetic evaluation using real FFmpeg 7.0 produced perfect lighting accuracy (5/5) and camera-motion accuracy (6/6), with a quality Spearman correlation of 0.87 against human labels ([implementation_status.md](file:///Users/karthikeyaunnam/Documents/MONTA/research_notes/MONTA project status and roadmap/implementation_status.md)).

A functional end-to-end pipeline exists in the Celery worker (`pipeline_tasks.py`, 354 lines), executing the full chain from intent analysis through context composition, director execution (which invokes video intelligence and story architecture), persistence of results, timeline IR generation, FFmpeg execution plan compilation, final MP4 rendering via MediaRenderer, output validation with ffprobe, and project status updates ([implementation_status.md](file:///Users/karthikeyaunnam/Documents/MONTA/research_notes/MONTA project status and roadmap/implementation_status.md)). This pipeline represents the real production path — but it bypasses the master graph, which remains stubbed for execution layers.

The shared infrastructure supporting these layers is notably robust. The `shared/` directory contains **10 contract modules** with frozen Pydantic models enforcing schema versioning, a provider abstraction supporting Gemini REST and OpenAI-compatible endpoints with `ResilientProvider` and `FallbackProvider` wrappers, hardware detection for Apple/NVIDIA/Intel silicon, calibration via isotonic and Platt fitting with ECE/MCE/Brier metrics, multi-model arbitration using Beta posterior reliability, observability with **30 metrics** and Prometheus-compatible endpoints, and a local AI runtime with Ollama, llama.cpp, and MLX adapters ([architecture_overview.md](file:///Users/karthikeyaunnam/Documents/MONTA/research_notes/MONTA project status and roadmap/architecture_overview.md); [implementation_status.md](file:///Users/karthikeyaunnam/Documents/MONTA/research_notes/MONTA project status and roadmap/implementation_status.md)).

## Execution layers are stubbed despite existing service code

The most significant structural finding is a **bifurcation between the master graph and the worker pipeline**. The LangGraph master graph wires all 14 layers but contains six stub nodes for Layers 8-13: `apply_style_node` returns an empty style config, `generate_timeline_node` returns an empty timeline, `process_audio_node` returns an empty audio config, `execute_edits_node` returns an empty edit result, `evaluate_node` returns a critic score of 0.0, and `render_node` returns empty output ([remaining_work.md](file:///Users/karthikeyaunnam/Documents/MONTA/research_notes/MONTA project status and roadmap/remaining_work.md)). Meanwhile, real service-layer code exists for many of these layers but is disconnected from the graph — the Style Engine has preset matching, the Timeline Generator has a working StoryToTimelineTranslator, the Edit Executor has a 315-line FFmpeg compiler with hardware encoder support, and the Render Farm has a hardware-aware MediaRenderer with progress reporting ([implementation_status.md](file:///Users/karthikeyaunnam/Documents/MONTA/research_notes/MONTA project status and roadmap/implementation_status.md)).

Layer 10 (Audio Studio) is the weakest execution layer at approximately **5% complete**, with all seven modules — music generator, DJ remix, mashup, sound FX, tempo matcher, voiceover, and beat extension — containing only TODO placeholders ([implementation_status.md](file:///Users/karthikeyaunnam/Documents/MONTA/research_notes/MONTA project status and roadmap/implementation_status.md)). Layer 12 (Critic System) is at approximately **10%**, with the evaluator returning a hardcoded 0.0 score and the retry logic producing empty focus areas. This makes podcast, tutorial, and wedding story patterns non-functional despite having narrative structures defined ([implementation_status.md](file:///Users/karthikeyaunnam/Documents/MONTA/research_notes/MONTA project status and roadmap/implementation_status.md); [remaining_work.md](file:///Users/karthikeyaunnam/Documents/MONTA/research_notes/MONTA project status and roadmap/remaining_work.md)).

The peripheral AI capability modules are almost entirely placeholder. The `vision/` directory (OpenCV scene detection, Qwen-VL inference, Gemini Vision client), `speech/` directory (Whisper transcriber, alignment, caption generator), and `models/` directory (Qwen 3, Llama 3 inference) are at **5-10% completion** with stub implementations only ([implementation_status.md](file:///Users/karthikeyaunnam/Documents/MONTA/research_notes/MONTA project status and roadmap/implementation_status.md)). The production path relies on the `shared/providers/` abstraction for cloud model access rather than these local modules. The `memory/` directory contains a parallel stub Layer 14 implementation (learning engine, feedback loop, Qdrant client, embeddings) that appears to be an earlier design iteration superseded by the production `narrative_memory.py` — a 286-line system with SQL stores and hierarchical Bayesian smoothing that itself has known issues including forced user ratings and upsert race conditions ([remaining_work.md](file:///Users/karthikeyaunnam/Documents/MONTA/research_notes/MONTA project status and roadmap/remaining_work.md)).

The backend API reflects this split: health, upload, projects, prompt analysis, metrics, and WebSocket progress endpoints are functional, but audio (5 endpoints), render, and export are stubs. The frontend at approximately **85%** supports the core user loop but has no desktop (Electron) implementation ([implementation_status.md](file:///Users/karthikeyaunnam/Documents/MONTA/research_notes/MONTA project status and roadmap/implementation_status.md)).

## Four known failures and unvalidated model integration persist

The launch readiness review documented **18 findings**, of which the critical bugs were addressed in Launch Cycle 1. Four golden test failures remain open: `cinematic_a24_mood` (energy spike), `cinematic_trailer_style` (pattern ends on resolve act instead of hero payoff), `travel_tokyo_night` (genre inferred as cinematic rather than travel), and `wedding_romantic_film` (pace inferred as medium with mood confidence below threshold) ([remaining_work.md](file:///Users/karthikeyaunnam/Documents/MONTA/research_notes/MONTA project status and roadmap/remaining_work.md)). These represent edge cases in genre inference, pace classification, and energy scoring that affect the golden dataset's 71% pass rate.

The most consequential gap is that **no real model integration has ever been executed**. All provider tests use mocks — the 9 live-provider tests skip without API credentials. No real Qwen, Qwen-VL, or Gemini API call has been made, meaning schema compliance, latency, and cost characteristics are entirely unknown ([remaining_work.md](file:///Users/karthikeyaunnam/Documents/MONTA/research_notes/MONTA project status and roadmap/remaining_work.md)). This is compounded by unvalidated evaluation infrastructure: the LLM story judge requires at least 30 human ratings with Spearman correlation of 0.6 or higher to be trusted, but no human ratings exist. Confidence calibration has been validated only on synthetic overconfident data (ECE drops from 0.17 to 0.05), with real-world ECE per field unknown ([remaining_work.md](file:///Users/karthikeyaunnam/Documents/MONTA/research_notes/MONTA project status and roadmap/remaining_work.md)).

Additional known issues include a **cross-tenant data leak** in ContextComposer where `previous_successful_projects` contains other creators' user and project IDs, signal thresholds calibrated only on synthetic noise textures rather than real phone footage, no duplicate or near-duplicate clip detection, no sub-clip segmentation (making long takes nearly unusable for short-form content), no task persistence or resume capability, no shared rate limiter across workers, and an FFmpeg input that is not sandboxed (no protocol whitelist, symlinks followed) ([remaining_work.md](file:///Users/karthikeyaunnam/Documents/MONTA/research_notes/MONTA project status and roadmap/remaining_work.md)). The narrative memory system also suffers from a forced `user_rating` field that requires inventing ratings for unrated projects, and a DELETE+INSERT upsert pattern that races under PostgreSQL concurrency ([remaining_work.md](file:///Users/karthikeyaunnam/Documents/MONTA/research_notes/MONTA project status and roadmap/remaining_work.md)).

## Roadmap targets GA after 33-40 engineer-weeks

The project follows a **4-phase roadmap** defined in the launch readiness review. Phase 1 (critical blockers, 3 weeks, 3 engineers) is mostly complete — the golden pass rate improved from 50% to 71%, seven critical bugs were fixed, and the evaluation stack was built — but live provider contract suite execution, CI with Python 3.11 and FFmpeg, and minimum observability remain outstanding ([remaining_work.md](file:///Users/karthikeyaunnam/Documents/MONTA/research_notes/MONTA project status and roadmap/remaining_work.md)). Phase 2 (production hardening, 5 weeks) targets full OpenTelemetry tracing, decision logging, task persistence and resume, shared intelligence cache over Redis, shared rate limiting, failure catalog, duplicate detection, user-facing edit diagnostics, API authentication, and a vendor data-processing review for privacy compliance ([remaining_work.md](file:///Users/karthikeyaunnam/Documents/MONTA/research_notes/MONTA project status and roadmap/remaining_work.md)).

Phase 3 (quality optimization, 8-10 weeks including labeling) is the longest phase and centers on building real datasets: a 3,000-prompt corpus, 8,000 labeled clips, at least 30 judge-validation ratings, and 2,000 pairwise comparisons per quarter. It also includes a four-tier story evaluator with validated judge agreement, confidence calibration on real outcomes, re-fitting signal thresholds on labeled footage, speech and transcript understanding, sub-clip moment segmentation, fitting selection weights from benchmark data rather than the current invented 0.5/0.35/0.15 values, and multi-language lexicon support ([remaining_work.md](file:///Users/karthikeyaunnam/Documents/MONTA/research_notes/MONTA project status and roadmap/remaining_work.md)). Phase 4 (scale readiness, 6 weeks) addresses distributed execution via Celery, multi-model arbitration cascade, narrative-memory holdout testing, checkpoint slimming, vendor-native structured output, cost-aware admission control, and load testing at 500 clips per project with 10x peak RPS ([remaining_work.md](file:///Users/karthikeyaunnam/Documents/MONTA/research_notes/MONTA project status and roadmap/remaining_work.md)).

The immediate next steps before GA are six concrete actions: run the live provider test suite with real API credentials, label approximately 200 real clips and run Layer 6 evaluation, collect at least 30 human story ratings for judge agreement testing, accumulate calibration outcomes and refit, enable the memory holdout at 10% traffic share, and regenerate the benchmark baseline on a clean commit SHA (the current baseline records a dirty SHA from uncommitted work) ([remaining_work.md](file:///Users/karthikeyaunnam/Documents/MONTA/research_notes/MONTA project status and roadmap/remaining_work.md)). The launch decision matrix gates internal dogfooding at Phase 1 completion, closed beta at 1,000 creators at Phase 2 completion plus golden benchmark, and general availability at Phase 3 acceptance plus Phase 4 load and cost criteria ([remaining_work.md](file:///Users/karthikeyaunnam/Documents/MONTA/research_notes/MONTA project status and roadmap/remaining_work.md)).

## Conclusion

MONTA's trajectory reveals a project that has prioritized architectural correctness and testability in its intelligence core while leaving the execution layer as a scaffold. The 199-test suite, golden dataset regression, and functional worker pipeline demonstrate engineering discipline, but the absence of any live model integration means the system's core value proposition — AI-driven editing quality — remains unvalidated against real providers. The disconnect between the stubbed master graph and the functional worker pipeline suggests the team chose to prove the intelligence path first, deferring graph integration until the execution services mature. The 33-40 engineer-week estimate to production-grade is realistic given the scope of remaining work: building out six execution layers, validating against real models and human raters, and hardening for production traffic. The critical insight is that Layers 8-13 are not the current bottleneck — the bottleneck is the validation data (real model outputs, human ratings, calibration outcomes) needed to trust the intelligence core already built. Once that validation exists, the execution layers can be wired into the graph with confidence that the creative decisions they execute are sound.
